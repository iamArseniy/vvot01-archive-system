# Готовый сценарий скринкаста (не более 15 минут)

Это почти дословный текст для записи: в каждом разделе указано, что показывать
и что говорить. Нормальная длительность — 12–14 минут. Долгое ожидание
`terraform apply` и `terraform destroy` можно вырезать, но начало команды и её
успешный результат обязательно оставьте в видео.

## Что подготовить до начала записи

Не начинайте запись, пока не выполнены эти пункты:

1. Подставьте свои значения в `terraform.tfvars`:

   ```hcl
   cloud_id    = "ВАШ_CLOUD_ID"
   folder_id   = "ВАШ_FOLDER_ID"
   bucket_name = "vvotNN-archive-unique-suffix"
   ```

   Вместо `NN` должен быть ваш двузначный номер студента. Имя бакета пишите
   только строчными латинскими буквами, цифрами и дефисами.

2. Проверьте CLI и получите токен:

   ```bash
   yc config get cloud-id
   yc config get folder-id
   export YC_TOKEN="$(yc iam create-token)"
   ```

3. Один раз выполните `terraform init`. Это подготовительная операция, её можно
   не тратить время показывать в видео.
4. Убедитесь, что система сейчас удалена: перед записью не должно быть старых
   ресурсов или старого `terraform.tfstate` от другого развёртывания.
5. Откройте заранее:
   - редактор с `openapi.yaml`, `function/index.py` и Terraform-файлами;
   - терминал в корне проекта;
   - консоль Yandex Cloud в нужном каталоге;
   - публичный Git-репозиторий проекта.
6. Увеличьте шрифт редактора и терминала. Закройте окна, где могут быть токены,
   ключи и другие секреты. Не открывайте `terraform.tfstate` на видео.

## 0:35–2:25 — обзор OpenAPI

### Что показывать

Откройте `openapi.yaml`. Последовательно прокрутите:

1. `POST /tasks`;
2. `GET /archives`;
3. `GET /archives/{key}`;
4. `GET /download/{key}`;
5. схемы `Task` и `Archive` внизу файла.

Задержите курсор на следующих строках:

- `validateRequestBody: true`;
- `type: cloud_ymq` и `action: SendMessage`;
- `x-yc-status-mapping: 202`;
- `action: Scan` и `action: GetItem`;
- `type: object_storage`;
- регулярное выражение UUIDv7.

### Что говорить

> API описан в формате OpenAPI 3.0. Основная точка входа — служебный домен API
> Gateway. Метод POST tasks принимает обязательные строковые поля name и url.
> Валидатор шлюза проверяет тело запроса: корректное задание отправляется прямо
> в Message Queue, а клиент получает статус 202 Accepted. Некорректное задание
> получает 400 Bad Request.
>
> Метод GET archives выполняет Scan документной таблицы archives. Метод GET
> archives key использует GetItem и возвращает одну запись либо 404. Метод GET
> download key напрямую получает ZIP из закрытого Object Storage. Ключ в пути
> проверяется по формату UUID версии 7 с расширением zip. Таким образом, для
> чтения данных отдельная HTTP-функция не нужна: API Gateway использует штатные
> интеграции Yandex Cloud.

## 2:25–4:20 — обзор функции архивирования

### Что показывать

Откройте `function/index.py` и покажите по порядку:

1. функцию `uuid7`;
2. `_download` и `_safe_filename`;
3. `_aws_resources`;
4. `process_task`;
5. `handler`.

В отдельном терминале запустите:

```bash
python3 -m unittest discover -s function -p 'test_*.py' -v
```

### Что говорить

> Триггер передаёт функции событие Message Queue. Обработчик извлекает JSON с
> полями name и url. Функция uuid7 формирует ключ, соответствующий RFC 9562:
> временная метка находится в старших битах, а версия устанавливается в 7.
>
> Затем исходный файл скачивается потоково во временный каталог. Имя очищается
> до базового имени, чтобы внутри ZIP нельзя было создать опасный путь вроде
> перехода в родительский каталог. После этого функция создаёт ZIP, загружает
> его в Object Storage и записывает в YDB поля name, url и key.
>
> Если запись в базу завершилась ошибкой, уже загруженный объект удаляется и
> исключение передаётся триггеру. После первой неуспешной попытки сообщение
> попадёт в очередь необработанных заданий. Здесь видно, что модульные тесты
> генерации UUID, безопасного имени и основного обработчика проходят успешно.

## 4:20–6:40 — обзор Terraform

### Что показывать

Открывайте файлы быстро, не читайте каждую строку:

1. `variables.tf` — три переменные;
2. `locals.tf` — вычисление префикса и роли;
3. `queues.tf` — обе очереди и `maxReceiveCount = 1`;
4. `function.tf` — функция и триггер;
5. `database.tf` — Serverless YDB и создание таблицы;
6. `storage.tf` — размер и закрытый доступ;
7. `api_gateway.tf` — применение `openapi.yaml` через `templatefile`.

### Что говорить

> Terraform принимает ровно три входные переменные: cloud id, folder id и
> bucket name. Префикс vvot с номером студента извлекается из имени бакета,
> поэтому дополнительная переменная не нужна. Все именуемые ресурсы получают
> этот префикс, а таблица называется строго archives по условию задания.
>
> Основная очередь имеет таймаут видимости 900 секунд, ожидание получения 20
> секунд и хранение сообщений одни сутки. После первой ошибки сообщение
> переводится в DLQ, где хранится 14 суток. Функция получает 256 мегабайт памяти
> и таймаут 600 секунд. Триггер берёт по одному сообщению без ожидания.
>
> База создаётся в режиме Serverless с ограничением 10 request units в секунду
> и размером один гигабайт. Таблица archives документная, поэтому она создаётся
> через DynamoDB-совместимый Document API. Бакет ограничен десятью гигабайтами,
> анонимный доступ отключён. Эта же конфигурация создаёт сервисные аккаунты и
> назначает все необходимые роли. Провайдер получает IAM-токен только из
> переменной окружения YC_TOKEN.

> показывает ресурсы, которые будут созданы. Применяю этот сохранённый план.
> Сейчас Terraform создаёт сервисные аккаунты и роли, две очереди, базу и
> документную таблицу, бакет, функцию, триггер и API Gateway.
>
> Развёртывание завершено успешно. В outputs получен служебный адрес API Gateway
> и адрес Swagger UI. Пользовательский домен не используется, что соответствует
> условию задания.

### Что дополнительно показать в консоли Yandex Cloud

Говорите:

## 8:30–11:50 — тестирование системы

### Что показывать

Запустите готовую сквозную проверку. В качестве файла используется небольшой
публичный README:

```bash
./tests/smoke_test.sh \
  "$(terraform output -raw api_gateway_url)" \
  "https://raw.githubusercontent.com/github/gitignore/main/README.md"
```

Скрипт должен последовательно показать статусы `400`, `202`, `200`, `200` и
`404`, ключ архива и список файлов внутри ZIP.

После теста можно на 20–30 секунд открыть:

- таблицу `archives` в YDB;
- объекты бакета;
- последние логи функции.

### Что говорить

> Сначала скрипт отправляет задание без обязательного URL. API Gateway отклоняет
> его со статусом 400, значит валидация работает. Затем отправляется корректное
> задание, и API отвечает 202 Accepted.
>
> Триггер получает сообщение и вызывает функцию. После обработки GET archives
> возвращает запись. Ключ имеет формат UUIDv7: в третьей группе первая цифра —
> 7. Запрос информации об архиве возвращает 200 и поля name, url и key.
> Скачивание также возвращает 200, а проверка ZIP показывает исходный файл
> внутри архива. Последний запрос использует отсутствующий, но корректный по
> формату ключ и получает 404 Not Found.
>
> В консоли YDB видна запись метаданных, в приватном бакете — ZIP-объект, а в
> логах функции — успешное выполнение. Таким образом, проверены создание,
> обработка, просмотр, скачивание и обработка ошибок.

## 11:50–13:45 — удаление ресурсов

### Что показывать

Запустите:

```bash
terraform destroy
```

Покажите запрос подтверждения, введите `yes`, затем финальную строку
`Destroy complete`. После этого обновите страницу ресурсов Yandex Cloud или
выполните `terraform state list` — вывод должен быть пустым.

### Что говорить

> В завершение удаляю систему той же Terraform-конфигурацией. Terraform сначала
> удаляет зависимые ресурсы, документную таблицу и API-компоненты, затем базу,
> очереди, бакет, ключи, роли и сервисные аккаунты. Для учебного бакета включён
> force destroy, поэтому созданный во время теста ZIP удаляется вместе с ним.
>
> Удаление завершено. Состояние пустое, а в каталоге Yandex Cloud больше нет
> ресурсов этой системы, поэтому после демонстрации они не продолжают
> потреблять облачные ресурсы.

## Если что-то пошло не так во время записи

- `403` сразу после создания ролей: подождите 20–60 секунд и повторите
  `terraform apply` или тест — IAM-роли распространяются не мгновенно.
- Задание долго не обрабатывается: новый триггер может активироваться несколько
  минут. Проверьте его статус и логи функции.
- Имя бакета занято: измените только уникальный суффикс после `vvotNN-`.
- Истёк IAM-токен: снова выполните `export YC_TOKEN="$(yc iam create-token)"`.
- Не показывайте ошибочную запись целиком: остановите запись, исправьте проблему
  и начните соответствующий фрагмент заново.
