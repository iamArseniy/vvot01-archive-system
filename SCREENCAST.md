# План скринкаста (до 15 минут)

Ниже готовый маршрут записи. Перед началом откройте терминал в корне проекта,
консоль Yandex Cloud и Swagger UI из `terraform output -raw swagger_url`.

## 0:00–1:00 — постановка задачи и архитектура

Покажите схему из задания и кратко проговорите поток:

1. `POST /tasks` проходит валидацию API Gateway и попадает в Message Queue.
2. Триггер забирает одно сообщение и вызывает функцию.
3. Функция скачивает файл, создаёт `<uuid_v7>.zip`, загружает его в приватный
   бакет и пишет `name`, `url`, `key` в документную таблицу `archives`.
4. Остальные GET-маршруты API Gateway обслуживает напрямую через YDB и Object
   Storage.

## 1:00–3:00 — OpenAPI

Откройте `openapi.yaml` и покажите:

- `POST /tasks`, строгую схему `Task` и `validateRequestBody`;
- замену ответа интеграции YMQ на `202` через `x-yc-status-mapping`;
- `Scan` для `GET /archives` и `GetItem` для `GET /archives/{key}`;
- проверку отсутствующей записи, возвращающую `404`;
- интеграцию `object_storage` для `GET /download/{key}`;
- Swagger UI на `/docs`.

## 3:00–5:00 — код функции

Откройте `function/index.py` и покажите:

- разбор формата события YMQ;
- собственную реализацию UUIDv7 по RFC 9562;
- безопасное имя файла без возможности ZIP Slip;
- потоковое скачивание во временный каталог и создание ZIP;
- загрузку в Object Storage и `PutItem` в YDB;
- компенсацию: удаление объекта, если запись метаданных завершилась ошибкой.

Запустите модульные тесты:

```bash
python3 -m unittest discover -s function -p 'test_*.py' -v
```

## 5:00–8:00 — Terraform и развёртывание

Покажите три переменные в `variables.tf`. Объясните, что `vvotNN-` извлекается
из `bucket_name`, поэтому четвёртая переменная не нужна. Затем покажите очередь,
DLQ, функцию, триггер, YDB, приватный бакет, роли и формирование OpenAPI через
`templatefile`.

Выполните:

```bash
export YC_TOKEN="$(yc iam create-token)"
terraform init
terraform validate
terraform plan -out main.tfplan
terraform apply main.tfplan
terraform output
```

В консоли Yandex Cloud быстро покажите созданные ресурсы с префиксом
`vvotNN-`, параметры очередей, 256 МБ/600 с у функции, 1/0 с у триггера,
10 RU/с и 1 ГБ у YDB, 10 ГБ и закрытый доступ у бакета.

## 8:00–12:30 — тестирование

Сначала в Swagger или `curl` отправьте некорректное задание и покажите `400`.
Затем запустите полный тест, передав публичную небольшую ссылку на файл:

```bash
./tests/smoke_test.sh \
  "$(terraform output -raw api_gateway_url)" \
  "https://example.org/path/to/a-small-public-file.txt"
```

Покажите `202`, появление записи, UUID версии 7 (первая цифра третьей группы —
`7`), информацию об архиве, содержимое ZIP и `404` для отсутствующего ключа.
При желании откройте логи функции и таблицу `archives` в консоли.

## 12:30–14:30 — удаление

Выполните и подтвердите:

```bash
terraform destroy
```

После завершения покажите пустые списки ресурсов в каталоге. Упомяните, что
`force_destroy = true` нужен для удаления непустого учебного бакета, а
документная таблица удаляется до базы.

## 14:30–15:00 — итог

Покажите публичный Git-репозиторий и перечислите три результата: OpenAPI,
функция, Terraform. На этом остановите запись.
